# Studiesphere — New Look Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Restyle the whole app to the approved pastel design, and turn the home screen into a dashboard.

**Architecture:** Design tokens in `src/app/globals.css` (Tailwind v4 `@theme`), self-hosted DM Sans, a small set of shared UI primitives and an inline-SVG icon set in `src/ui/`, an app shell with a left icon rail for every `/app` route. Screens are rebuilt on those primitives; the canvas engine is untouched except the renderer's background (dot grid) and the React chrome around it.

**Tech Stack:** Next.js 16.4 App Router, Tailwind v4, `@fontsource-variable/dm-sans` (npm, self-hosted), existing Supabase queries.

**Spec:** Approved mockup "Studiesphere — New look", https://claude.ai/artifact/Hy9HiNpHYK3N68UraD4hag (artboards: Home dashboard, Subject, Notebook, Notes canvas, Sign in).

## Global Constraints

- Look (from the mockup, exact values): ground `#F6F2EE`; panel/rail `#EFE7E0`; card `#FFFFFF`; ink `#1B1A1F`; muted text `#5F5A66`; pastels pink `#F6CFCF`, peach `#F9DFC0`, lavender `#DCD6FA`, mint `#C9EEDB`, sky `#CFE3F7`, butter `#F4EBB5`; today highlight `#F4D35E`; saved dot `#2F9E6B`. Radii: cards 24–28 px, banners 32 px, pills 999 px, icon buttons 52 px circles in the rail, 44 px elsewhere. Font DM Sans (400/500/600), self-hosted (no Google Fonts request at runtime or build).
- Light only (`color-scheme: light`) — keep the dark-mode fix.
- Every user-facing string in `src/i18n/en.ts`; touch targets ≥ 44 px; real `<button>`/`<a>`/`<label>`; text contrast ≥ 4.5:1.
- Must work on iPad Safari (landscape and portrait) and laptops; at phone width the rail becomes a bottom bar and panels stack.
- Do not change canvas engine behaviour (`src/canvas/` outside `react/` and the renderer background), persistence, auth logic or the database. No migrations.
- Existing tests keep passing; update selectors only where labels intentionally change.
- Subject colours: the 6 stored subject colours map to the 6 pastels above (store the pastel hex for new subjects; map old stored values to the nearest pastel when displaying).

## Review Focus

1. **iPad portrait (834 px wide)** → dashboard right panel drops below the main column, nothing overflows horizontally. Test: e2e at 834×1194 asserts `document.documentElement.scrollWidth <= innerWidth`.
2. **Phone width (390 px)** → rail becomes a bottom bar; all nav targets still reachable. Test: e2e at 390×844 nav links visible.
3. **A user with no subjects / no pages** → dashboard shows a friendly empty state with a "New subject" action, not empty sections. Test: dashboard unit test with empty data.
4. **Long names** (60-char subject or page title) → truncate with ellipsis, cards keep their size. Test: component test.
5. **Canvas chrome over drawing** → toolbar/pills never block drawing outside their own bounds (pointer events pass through the empty areas of the top bar). Test: e2e draws a stroke starting just below the toolbar row.
